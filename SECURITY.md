# Security Policy

Thank you for helping keep **Project Freedom** secure.

We take security seriously and appreciate responsible disclosure of vulnerabilities.

---

# Supported Versions

The following table indicates which versions of Project Freedom currently receive security updates.

| Version | Supported           |
| ------- | ------------------- |
| 1.x.x   | ✅ Yes               |
| 0.x.x   | ⚠️ Development only |
| < 0.1.0 | ❌ No                |

> **Note:** During the early development phase (0.x.x), security fixes may be released without maintaining backward compatibility.

---

# Reporting a Vulnerability

If you discover a security vulnerability, **please do not create a public GitHub Issue**.

Instead, report it privately so we have an opportunity to investigate and resolve the issue before public disclosure.

Please include as much information as possible, such as:

* A clear description of the vulnerability.
* Steps required to reproduce the issue.
* The affected version.
* Potential impact.
* Proof of Concept (PoC), if available.
* Any suggested mitigation or fix.

---

# Response Process

After receiving a report, we will:

1. Acknowledge receipt of the report.
2. Investigate the issue.
3. Assess its severity and impact.
4. Develop and test a fix.
5. Publish the fix in a future release.
6. Credit the reporter (if they wish to be acknowledged).

---

# Disclosure Policy

We follow a **responsible disclosure** process.

Please allow reasonable time for investigation and remediation before publicly disclosing any vulnerability.

---

# Security Best Practices

When using Project Freedom:

* Keep your installation up to date.
* Apply the latest security patches.
* Protect API keys and credentials.
* Follow the principle of least privilege.
* Avoid exposing sensitive configuration files.
* Report suspicious behavior immediately.
